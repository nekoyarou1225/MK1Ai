# MK1AI_REMAINING_SECURITY_RISKS.md — 残存セキュリティリスクおよび未検証事項の整理

## 1. 概要

本改修（Remediation V2）を完了した後も、環境およびリソースの制限により依然として残るリスクを以下に列挙する。

## 2. リスクマトリクス

| ID | リスク内容 | 重大度 | 回避策 / 将来の対応 |
|---|---|:---:|---|
| **R-13** | **実 NIC での XDP 動作未検証** | **High** | 物理 NIC を備えた Bare-metal 環境での `XDP_NATIVE_ATTACHED` 検証が必要。 |
| **R-14** | **AI モデル重みの動的改ざん** | **Med** | Head C によるメモリ完全性チェックを実装するが、カーネルレベルの Integrity Measurement (IMA) との統合が望ましい。 |
| **R-15** | **デコイ内での高度な特権昇格** | **Med** | ハニーポットが侵害された際、`on_core_emergency_isolate` が呼ばれるまでのミリ秒単位の窓を突かれる可能性。 |
| **R-16** | **QKD ハードウェアエミュレーションの限界** | **Low** | 量子ビット誤り率 (QBER) のシミュレーションは論理的整合性のみ。実機による光学的ノイズ特性の検証が必要。 |

## 3. 結論

MK1Ai は論理的には「100% Fail-Closed」を達成しているが、物理的な攻撃（サイドチャネル、ハードウェアバックドア）については、本ソフトウェアスタックの外部にある保護レイヤー（TPM、Secure Boot）との補完が必要である。
